A multilingual medical-exploration application built with React and TypeScript, with a versioned matching engine, Supabase research storage and staff authentication, an administrative portal, and shared web/mobile code.

Read this first

This is a repository snapshot dated 25 September 2026, based on Git revision @@GIT_COMMIT@@ and the accompanying source, migrations and test reports. A file existing in the repository does not prove that it has been deployed.

The live database, provider accounts and app stores were not contacted to verify release status while preparing this PDF. The guide contains no passwords, API-key values, access tokens, patient information or research responses.

01 · Return after one year

Your first hour back

  1. Recover ownership. Locate GitHub, Supabase, hosting/DNS, backup, SMTP and signing-key access through your password manager. Check who can recover each account and its MFA.
  2. Identify what is actually live. Compare the deployed Git SHA, hosting release and database migration history. Do not assume main, this PDF or the latest local folder matches production.
  3. Protect the current data. Confirm the latest encrypted backup and successful restore drill. Do not upgrade, migrate, clean up or delete data before this check.
  4. Reproduce the recorded environment. Start from the lockfile and Node 24 baseline, in a branch. Use synthetic staging data, not the real research database.
  5. Run the checks. Frontend tests are not substitutes for real Supabase database/security tests. Check access, submission receipts, map visibility and exports.
  6. Review the changes since this date. Runtime support, security advisories, provider prices, consent rules and native-store requirements will have moved. Plan upgrades separately from recovery.
Do not “fix everything” with a bulk dependency update. First reproduce the baseline; then upgrade one component at a time, with tests and a rollback plan.

A submission’s lifecycle

Select an audience → answer in memory → obtain the ranking with a published catalog → choose whether to save with consent → freeze the submission UUID, answers, catalog and scoring context → send or queue it → call it saved only when the server returns that same UUID.

Retrying the same accepted payload returns the original receipt. Reusing its ID with different content must fail, not silently update the research row.

Not part of this architecture: no required AI API, trained-model service, dedicated Express/Next.js server, Redis, Kubernetes or public response-file bucket. A static frontend host does not provide database backups.

Primary code: src/App.tsx, src/lib/supabase.ts, src/lib/scoring.ts, supabase/migrations/.

05 · Product rules and content

Behavior to preserve

Three audiences

Before medicine: curious explorers.
During medicine: medical students.
After medicine: specialists.

Audience selection is a questionnaire category, never an administrative permission.

Three languages

English, Romanian and French use repository translation dictionaries. Change every relevant language together; retain stable question IDs and canonical specialty names.

Questionnaire and results

  • The main questionnaire contains 81 ratings on the 1–10 scale; career values and five dimension priorities are separate inputs. Mobile controls must not change the underlying numeric scale.
  • Students and explorers may add an optional written perspective on medicine. Saving remains a choice. A student’s optional study year is 1–6; explorers have no study year.
  • Specialists can answer the main questionnaire or skip directly to the qualitative interview. Skipping is explicit and produces no invented quantitative ranking.
  • The specialist interview asks about the specialty now, changes over time, its most important quality, choosing it again, and a question a student should ask. A “no” rechoice requires an explanation.
  • Results show the top 10 specialties with narratives and bibliography where supplied. Do not reinstate removed calculated-analysis or empty-reference sections by accident.
  • Back navigation and scroll-to-top are shared behaviors. Unfinished answers remain in memory across in-app navigation but are not restored after reload or closing.

Editorial ownership

The Romanian source is at docs/sources/specialist-specialty-narratives-ro.txt. It has 58 numbered sections but 57 unique specialties: two Pulmonology sections merge; Pathology is absent. Do not label every catalog narrative specialist-authored. src/data/specialtyNarratives.ts and its JSON parts preserve provenance and translations.

The staff editor can change versioned descriptions, clinical summaries and target profiles without editing the code. Only authorized publication makes a draft active.

Branding uses BrandLogo.tsx, public/branding/compass.svg and generated web/native icons. npm run generate:icons regenerates assets; test:icons checks them. The supplied raster artwork is retained, not the only UI logo format.

Check src/config/features.ts: public research CTA, specialty comparison, methodology and opposite-fit controls are currently off. A component existing in the code does not mean its public entry control is enabled. Navigation uses appNavigation.ts, not React Router.

06 · Scoring and reproducibility

Understand what the score means

This is a deterministic compatibility engine, not an AI diagnosis, a probability of career success or an objectively tested measure of competence. Changing a specialty profile changes a model configuration, not proof of validity.

  1. Normalize ratings: ((answer − 1) / 9) × 100. Trait mappings define weights and forward/reverse alignment.
  2. Build measured traits: weighted combinations of mapped answers. Selected career values do not inflate an already measured trait’s score; they adjust matching importance.
  3. Handle value-only evidence: a selected value can introduce a trait absent from item measurement. The current selected value-only level is 90. Unmeasured traits are not silently replaced with 50.
  4. Compare with each specialty: combine trait similarity with profile importance, dimension-priority multiplier and career-value multiplier. Divide by contributing weights. Missing dimensions can be unavailable rather than a false zero-fit.
  5. Rank at full precision: display rounding must not create research ties. A preferred or actual specialty is not an input to the score.

08 · Security and privacy

Identity is not authorization

ActorAllowed scope
Public participantPublished catalog, validated consented submission, approved public aggregates only when enabled. No raw research reads.
Ordinary signed-in userAuthentication alone grants no research permission. Being a specialist respondent grants no staff access.
ResearcherAuthorized research reads, analyses/exports and private map; owner-specific saved filters/runs.
DoctorResearch access plus catalog draft editing and public-map settings; synthetic recipe controls.
ProfessorDoctor capabilities plus governed catalog publication and restoration.

Rules that must survive future refactoring

  • Authorize on the server using enabled private.researchers membership. Do not trust audience selection or user-editable JWT metadata.
  • Use explicit grants, RLS and a restricted function search path. Privileged SQL functions need role checks and revoked default public execution.
  • Never put secret/service-role keys, database passwords or operator tokens in VITE_*, the mobile bundle, Git, screenshots or this handbook.
  • On expiry or revocation, clear private UI state and deny subsequent API calls. Hiding controls is not access control; previously downloaded files cannot be remotely erased.
  • Do not log answers, narratives or tokens. Free text can identify someone even when names/emails are not requested. “No name field” is not a blanket anonymity claim.

Local storage is deliberately split

Unsubmitted questionnaire drafts: memory only; no save/resume panel. Explicitly consented pending submissions: a separate frozen retry queue persists until sent, rejected, expired or removed. Browser storage is not encrypted; native storage uses the secure-storage adapter. A queued contribution is not yet saved on the server.

The current queue is bounded (10 entries and approximately one million serialized characters); automatic retry ends after seven days. Do not clear all browser data casually if an unsent consented contribution may still be present.

Outstanding: approve consent/provenance disclosures, retention/deletion and research governance; implement approved anonymous-submission anti-abuse before broad recruitment. The staff analytics rate limit is not CAPTCHA or an Internet firewall.

The map may correctly be empty

The public switch defaults to disabled and fails closed when it cannot be checked. Disabled means no public links, previews, geography widgets or public data endpoint access. Authorized private research access remains separate.

When enabled, the map shows published submissions, not live totals or unique people. Only eligible closed-month cells with at least 10 submissions are released, rounded down to multiples of 5. Missing geography, the current month, suppressed cells and skipped specialist questionnaires do not become public counts.

The monthly release is sealed and cannot be casually rewritten. pg_cron schedules publication at 01:15 on the first day of each month; check its history and UTC month boundaries. A newly submitted record need not appear immediately.

Testing without polluting research

Authorized editors can create/remove a recipe generating 5 specialists, 5 students and 5 explorers. Test mode stays separate, marks exports synthetic, and blocks live server analyses/settings changes. Remove the exact recipe through the UI; never delete real response tables to “clean up test data.”

A visibility check is refreshed on lifecycle events and every 30 seconds. Offline/failed checks hide the public map. Approved data previously seen by someone cannot be clawed back.

10 · Research interpretation and exports

Reproducible does not mean validated

Live cohort

A saved named filter. New submissions can change its membership and counts.

Frozen result

A recorded analysis with filters, parameters, digest, model versions, time and derived results. Not a full raw-data backup.

Always report the denominator: global submissions, filtered submissions, eligible questionnaires and exclusions are different totals. Missing optional metadata does not automatically exclude a valid questionnaire. Cohort comparisons may overlap and are not automatically independent samples.

What the analyses calculate

  • Items: original 1–10 bins, n, missingness, mean, median, sample SD, floor/ceiling counts. Pearson correlations use eligible complete questionnaires; constant items give no coefficient.
  • Specialist evaluation: Top-1/3/5/10 recall, median rank and mean reciprocal rank. Inclusive ties use best rank, conservative ties worst rank. No rounded-score ties.
  • Groupings: submission-weighted and equally weighted observed-specialty summaries; language/metadata strata and trait profiles/distributions. Review flags never automatically remove people or questions.
  • Not claimed: population confidence intervals without a sampling basis, validated latent traits, factor analysis, language invariance or reliable unique-person counts.

Choose the right export path

PathBounds and interpretation
Browser exportUp to 1,000 filtered submissions; raw-wide, long, analytical CSV or JSON; metadata and SHA-256. Created-at cutoff/keyset pagination is not an atomic database snapshot.
Server analysisUp to 5,000 submissions, 20 retained results per owner, 10-second SQL timeout; 50 named cohorts. 30 successful expensive operations per five minutes per account.
Operator worker5,000 rows / 32 MiB input / 128 MiB output; progress, cancellation and three-minute default overall deadline. Before/after cohort checksum comparison; private files outside Git.

The operator uses an authorized staff access token, not a service key, and evaluates the explicitly frozen repository-source catalog unless a separate candidate is supplied. It does not silently use the live published model. Candidate comparison fits no parameters and promotes nothing.

Use npm run research:export -- --help and docs/RESEARCH_OPERATOR.md. Distribute CSVs only with their manifest/model provenance. Digests are integrity labels, not encryption or anonymization. Training a future model requires fitting inside training splits and independent evaluation.

Installable web application

14 · Operations and budget

Protect the data before optimizing costs

A backup is only useful if it restores

Assign an owner. Keep encrypted off-site backups outside Git and public storage. Preserve schema, data, relevant roles/configuration, migration history, Auth/SMTP settings, recovery material and storage objects if any. A CSV research export is not a database backup.

Rehearse restoration into an isolated compatible environment with outgoing email/hooks disabled. Check integrity, row counts, roles/RLS, published versions, consent, idempotency and the deletion ledger. Do not replay every migration over an already current restored schema.

Documented pilot targets—not guarantees—are at most 24 hours of recoverable data loss during recruitment and recovery within one business day. The proposed rotation is seven daily/four weekly encrypted copies, with monthly restore drills, subject to approved retention obligations.

Small glossary

RPC: a database function exposed through an API. RLS: row-level security. JWT: signed identity/session token, not automatic permission. Migration: ordered database change. PWA: installable web app. Catalog: versioned specialty content and target profiles. Cohort: selected submissions. Idempotency: repeat the same write safely without duplicating it. Checksum: integrity/version identifier, not encryption. CI: automated checks/builds. RPO/RTO: acceptable data-loss window / recovery-time objective.
